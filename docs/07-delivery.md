> **سطح:** مبتدی

> **هدف:** آماده‌سازی یک گزارش قابل‌خواندن، قابل‌ویرایش و قابل‌پردازش مجدد برای تحویل دانشگاه

## 🎯 در این درس چه یاد می‌گیریم؟

در پایان این درس می‌توانید:

- خروجی نهایی PDF را تولید کنید.
- تفاوت فایل‌های اصلی و کمکی LaTeX را تشخیص دهید.
- فایل‌های لازم برای تحویل را جمع‌آوری کنید.
- یک فایل ZIP استاندارد بسازید.
- مطمئن شوید تصاویر و فایل‌های وابسته داخل ZIP هستند.
- پروژه را پس از استخراج دوباره پردازش کنید.
- از اشتباهات رایج هنگام تحویل گزارش جلوگیری کنید.

## ۱. چرا فقط PDF همیشه کافی نیست؟

وقتی با LaTeX گزارش می‌نویسیم، دو نوع خروجی مهم داریم.

**فایل PDF:** نسخه نهایی گزارش است که می‌توان آن را مطالعه یا چاپ کرد.

**فایل TEX:** کد منبع گزارش است که می‌توان آن را ویرایش و دوباره پردازش کرد.

اگر استاد فقط PDF بخواهد، معمولاً تحویل همان PDF کافی است.

اما اگر استاد بخواهد مطمئن شود گزارش با LaTeX نوشته شده، ممکن است فایل‌های منبع پروژه را نیز درخواست کند.

در این حالت، **فقط ارسال PDF کافی نیست.**

بهتر است تمام فایل‌های لازم برای بازسازی گزارش را در یک فایل ZIP قرار دهیم.

---

## ۲. بعد از پردازش LaTeX چه فایل‌هایی ایجاد می‌شوند؟

فرض کنید فایل اصلی گزارش `main.tex` است.

بعد از پردازش ممکن است فایل‌هایی مانند این‌ها مشاهده کنید:

```text
OS-Lab-Report/
├── main.tex
├── main.pdf
├── main.aux
├── main.log
├── main.out
├── main.toc
├── main.synctex.gz
└── images/
    ├── terminal.png
    └── system-info.png
```

همه این فایل‌ها نقش یکسانی ندارند.

### فایل‌های اصلی

| فایل | کاربرد |
|---|---|
| `.tex` | کد منبع گزارش |
| `.pdf` | خروجی نهایی |
| `.png` / `.jpg` | تصاویر موردنیاز |
| `.bib` | اطلاعات منابع، در صورت استفاده |
| `.sty` | بسته سفارشی پروژه، در صورت استفاده |
| `.cls` | کلاس سفارشی پروژه، در صورت استفاده |

### فایل‌های کمکی

| فایل | کاربرد |
|---|---|
| `.aux` | اطلاعات کمکی ارجاع‌ها |
| `.log` | گزارش پردازش و خطاها |
| `.toc` | اطلاعات فهرست مطالب |
| `.lof` | اطلاعات فهرست تصاویر |
| `.lot` | اطلاعات فهرست جدول‌ها |
| `.out` | اطلاعات کمکی برخی قابلیت‌ها |
| `.synctex.gz` | هماهنگی بین کد و PDF |

فایل‌های کمکی معمولاً هنگام پردازش دوباره ساخته می‌شوند و برای تحویل عادی پروژه ضروری نیستند.

**استثنا:** اگر استاد صراحتاً همه فایل‌ها، گزارش خطا یا خروجی‌های خاصی را درخواست کرده باشد، مطابق همان دستور عمل کنید.

---

## ۳. کدام فایل‌ها را باید داخل ZIP بگذاریم؟

برای یک گزارش معمولی، پیشنهاد می‌کنیم این فایل‌ها را قرار دهید:

```text
OS-Lab-Report/
├── main.tex
├── main.pdf
└── images/
    ├── terminal.png
    └── system-info.png
```

اگر پروژه شما از چند فایل TEX استفاده می‌کند، همه آن‌ها را نیز اضافه کنید.

مثلاً:

```text
OS-Lab-Report/
├── main.tex
├── introduction.tex
├── results.tex
├── conclusion.tex
├── main.pdf
└── images/
    ├── step-01.png
    ├── step-02.png
    └── result.png
```

اگر از فایل‌های `bib`، `sty`، `cls` یا منابع داده دیگر استفاده کرده‌اید، فایل‌های موردنیاز را هم قرار دهید.

### یک قانون مهم

هر فایلی که پروژه برای تولید دوباره PDF به آن نیاز دارد، باید داخل ZIP باشد؛ مگر اینکه جزو بسته‌های استاندارد نصب‌شده LaTeX باشد.

## ۴. آماده‌سازی PDF نهایی

قبل از ساخت ZIP، ابتدا PDF را بررسی کنید.

### مرحله اول: باز کردن پروژه

فایل `main.tex` را در TeXstudio باز کنید.

### مرحله دوم: انتخاب موتور پردازش

از مسیر زیر بررسی کنید:

`Options → Configure TeXstudio → Build`

موتور پردازش روی `XeLaTeX` باشد.

### مرحله سوم: ذخیره فایل

کلیدهای زیر را فشار دهید:

`Ctrl + S`

### مرحله چهارم: پردازش سند

با `F5` سند را پردازش کنید.

اگر گزارش دارای فهرست مطالب یا ارجاع‌های خودکار است، معمولاً لازم است حداقل دو بار پردازش شود.

### مرحله پنجم: بررسی PDF

فایل نهایی را باز کنید و موارد زیر را بررسی کنید:

- عنوان و مشخصات دانشجو درست باشد.
- متن فارسی خوانا باشد.
- تصاویر به‌درستی نمایش داده شوند.
- جدول‌ها از صفحه بیرون نزده باشند.
- فرمول‌ها درست نمایش داده شوند.
- شماره صفحات صحیح باشد.
- فهرست مطالب به‌روز باشد.
- ارجاع‌ها به‌جای شماره، علامت سؤال نداشته باشند.
- صفحه خالی ناخواسته وجود نداشته باشد.

**نکته:** ساخته شدن PDF لزوماً به معنای بی‌خطا بودن کامل گزارش نیست. پیام‌های خطا و هشدار مهم را هم بررسی کنید.

## ۵. نام‌گذاری مناسب فایل‌ها

برای تحویل دانشگاهی، بهتر است نام فایل ZIP مشخص و قابل‌شناسایی باشد.

مثلاً:

```text
OS-Lab-02_StudentID.zip
```

یا:

```text
14030000000_Lab02.zip
```

به‌جای `StudentID` یا شماره نمونه، شماره دانشجویی خودتان را قرار دهید.

### پیشنهاد نام‌گذاری

از نام‌های کوتاه، انگلیسی و بدون فاصله استفاده کنید.

برای مثال:

**مناسب:**

```text
14030000000_OS_Lab02.zip
```

**نامناسب:**

```text
final-final-new-last-version.zip
```

نام مناسب کمک می‌کند استاد و دانشجو نسخه نهایی را راحت‌تر شناسایی کنند.

## ۶. ساخت ZIP در ویندوز

### روش گرافیکی

1. پوشه پروژه را باز کنید.
2. مطمئن شوید فایل‌های اصلی و تصاویر داخل آن قرار دارند.
3. روی پوشه پروژه راست‌کلیک کنید.
4. در ویندوز ۱۱ از گزینه `Compress to ZIP file` استفاده کنید.
5. در برخی نسخه‌های ویندوز ۱۰ از مسیر `Send to → Compressed (zipped) folder` استفاده کنید.
6. نام فایل ZIP را تغییر دهید.

برای مثال:

```text
14030000000_OS_Lab02.zip
```

### بررسی ZIP

روی فایل ZIP دوبار کلیک کنید.

مطمئن شوید پوشه پروژه، فایل TEX، فایل PDF و تصاویر موردنیاز داخل آن هستند.

**توجه:** فقط تغییر دادن پسوند یک پوشه یا فایل به `.zip` باعث فشرده‌سازی واقعی نمی‌شود.

## ۷. ساخت ZIP در اوبونتو با محیط گرافیکی

در اوبونتو می‌توانید بدون استفاده از ترمینال هم ZIP بسازید.

1. برنامه Files را باز کنید.
2. وارد مسیر پروژه شوید.
3. روی پوشه گزارش راست‌کلیک کنید.
4. گزینه فشرده‌سازی مانند `Compress` را انتخاب کنید.
5. در صورت نمایش انتخاب فرمت، ZIP را انتخاب کنید.
6. نام فایل را مشخص کنید.
7. عملیات فشرده‌سازی را انجام دهید.

نام گزینه‌ها ممکن است با توجه به نسخه اوبونتو و برنامه مدیریت فایل کمی متفاوت باشد.

---

## ۸. ساخت ZIP در اوبونتو با ترمینال

اگر می‌خواهید از ترمینال استفاده کنید، ابتدا ابزار ZIP را نصب کنید:

```bash
sudo apt update
sudo apt install zip unzip
```

### توضیح دستورها

- `zip`: ساخت فایل ZIP
- `unzip`: استخراج فایل ZIP

فرض کنید پوشه پروژه داخل `Documents` قرار دارد.

ابتدا به پوشه اسناد بروید:

```bash
cd ~/Documents
```

سپس:

```bash
zip -r 14030000000_OS_Lab02.zip OS-Lab-Report/
```

### توضیح خط‌به‌خط

**`zip`:** برنامه فشرده‌سازی.

**`-r`:** قرار دادن پوشه و تمام زیرپوشه‌های آن داخل ZIP.

**`14030000000_OS_Lab02.zip`:** نام فایل خروجی.

**`OS-Lab-Report/`:** پوشه‌ای که می‌خواهیم فشرده کنیم.

بعد از پایان دستور، فایل ZIP در پوشه فعلی ساخته می‌شود.

### بررسی محتوای ZIP

برای دیدن فهرست فایل‌ها:

```bash
unzip -l 14030000000_OS_Lab02.zip
```

این دستور بدون استخراج، نام فایل‌های موجود داخل ZIP را نمایش می‌دهد.

## ۹. پاک‌سازی فایل‌های کمکی قبل از تحویل

گاهی پوشه پروژه تعداد زیادی فایل کمکی دارد.

برای تحویل مرتب‌تر می‌توانید فقط فایل‌های اصلی را در یک پوشه جداگانه کپی کنید.

مثلاً:

```text
Submission/
├── main.tex
├── main.pdf
└── images/
    ├── terminal.png
    └── system-info.png
```

این روش برای دانشجوهای مبتدی امن‌تر از حذف گروهی فایل‌هاست.

### آیا می‌توان فایل‌های کمکی را حذف کرد؟

بله، بسیاری از فایل‌های کمکی مانند `.aux`، `.log` و `.toc` قابل بازسازی هستند.

اما:

- فایل‌های `.tex` را حذف نکنید.
- تصاویر موردنیاز را حذف نکنید.
- فایل‌های سفارشی پروژه را حذف نکنید.
- قبل از حذف هر فایل ناشناخته، کاربرد آن را بررسی کنید.

**پیشنهاد:** پوشه اصلی پروژه را دست‌نخورده نگه دارید و نسخه مخصوص تحویل را جداگانه بسازید.

## ۱۰. مهم‌ترین آزمون: آیا پروژه بعد از استخراج کار می‌کند؟

این مرحله از ساخت ZIP هم مهم‌تر است.

چون ممکن است گزارش روی کامپیوتر خودتان درست کار کند، ولی فایل‌های لازم را داخل ZIP نگذاشته باشید.

### روش آزمون

1. فایل ZIP را بسازید.
2. آن را در یک پوشه جدید استخراج کنید.
3. وارد پوشه استخراج‌شده شوید.
4. فایل `main.tex` را با TeXstudio باز کنید.
5. موتور XeLaTeX را انتخاب کنید.
6. فایل را پردازش کنید.
7. PDF تولیدشده را بررسی کنید.

اگر پردازش موفق باشد، احتمال اینکه فایل‌های ضروری پروژه را فراموش کرده باشید بسیار کمتر می‌شود.

### یک محدودیت مهم

موفقیت روی سیستم خودتان تضمین نمی‌کند که پروژه بدون نصب بسته‌ها و فونت‌های لازم روی هر سیستم دیگری نیز پردازش شود.

بنابراین بهتر است فونت‌های استفاده‌شده و موتور پردازش را هم مشخص کنید.

---

## ۱۱. اضافه کردن فایل راهنمای پروژه

برای پروژه‌های چندفایلی یا پروژه‌هایی که استاد باید آن‌ها را دوباره پردازش کند، می‌توانید یک فایل متنی ساده با نام `BUILD.txt` اضافه کنید.

نمونه محتوا:

```text
Project: Operating Systems Laboratory Report

Main source file: main.tex
Compiler: XeLaTeX

Required:
- A LaTeX distribution with XeLaTeX
- XePersian package
- Fonts used in main.tex

Build steps:
1. Open main.tex in TeXstudio.
2. Select XeLaTeX as the compiler.
3. Compile twice if references or contents need updating.
4. Open main.pdf.

All project images are stored in images/.
```

این فایل برای همه گزارش‌ها اجباری نیست، اما می‌تواند بازسازی پروژه را آسان‌تر کند.

## ۱۲. اگر استاد همه فایل‌های LaTeX را بخواهد چه کنیم؟

فرض کنید استاد اعلام کرده است:

«تمام فایل‌های مورد استفاده در LaTeX را ZIP کنید تا مشخص شود گزارش با LaTeX نوشته شده است.»

در این حالت، پیشنهاد ما:

1. فایل اصلی `main.tex` را قرار دهید.
2. همه فایل‌های TEX دیگر پروژه را اضافه کنید.
3. تمام تصاویر مورد استفاده را قرار دهید.
4. فایل‌های منبع یا قالب سفارشی را در صورت وجود اضافه کنید.
5. خروجی نهایی PDF را نیز قرار دهید.
6. در صورت نیاز فایل `BUILD.txt` را اضافه کنید.
7. ZIP را استخراج و دوباره پردازش کنید.

به این ترتیب استاد هم گزارش نهایی را مشاهده می‌کند و هم به کد منبع آن دسترسی دارد.

اگر استاد دقیقاً درخواست کرده باشد که حتی فایل‌های کمکی هم ارسال شوند، از دستور او پیروی کنید.

## ۱۳. اشتباهات رایج هنگام تحویل

### اشتباه اول: ارسال فقط PDF

اگر استاد فایل منبع خواسته باشد، PDF به‌تنهایی کافی نیست.

### اشتباه دوم: فراموش کردن تصاویر

اگر تصاویر در ZIP نباشند، ممکن است هنگام پردازش خطای `File not found` دریافت شود.

### اشتباه سوم: ارسال نسخه قدیمی PDF

ممکن است فایل TEX را اصلاح کرده باشید ولی PDF را دوباره نساخته باشید.

همیشه بعد از آخرین ویرایش، PDF را دوباره تولید کنید.

### اشتباه چهارم: اشتباه بودن فایل اصلی

در پروژه‌های چندفایلی باید مشخص باشد کدام فایل برای پردازش استفاده می‌شود.

معمولاً نام آن را `main.tex` می‌گذاریم.

### اشتباه پنجم: وجود اطلاعات محرمانه

قبل از ارسال ZIP، فایل‌های پروژه و تصاویر را بررسی کنید.

از قرار دادن موارد زیر خودداری کنید:

- رمز عبور
- توکن‌های دسترسی
- کلیدهای خصوصی
- اطلاعات شخصی غیرضروری
- فایل‌های نامرتبط با گزارش

### اشتباه ششم: آزمایش نکردن ZIP

ممکن است ZIP ساخته شود، اما ناقص باشد.

حتماً یک بار آن را استخراج کنید و محتوایش را بررسی کنید.

گزارشی را که در درس‌های قبلی ساخته‌اید آماده تحویل کنید.

### مرحله سوم

یک پوشه به نام `Submission` بسازید.

### مرحله چهارم

فایل‌های لازم را داخل آن کپی کنید.

### مرحله پنجم

از پوشه `Submission` یک ZIP بسازید.

### مرحله ششم

ZIP را در پوشه‌ای جدید استخراج کنید.

### مرحله هفتم

از نسخه استخراج‌شده دوباره PDF بگیرید.

### معیار موفقیت

اگر نسخه استخراج‌شده ZIP تمام فایل‌های ضروری را دارد و می‌تواند گزارش را دوباره تولید کند، پروژه شما برای تحویل آماده است.
