در پایان این درس می‌توانید:

- تفاوت خطا، هشدار و پیام اطلاع‌رسانی را تشخیص دهید.
- خطاهای TeXstudio را بخوانید.
- مشکلات مربوط به XeLaTeX را برطرف کنید.
- خطاهای فونت فارسی و بسته XePersian را تشخیص دهید.
- مشکلات تصاویر، جدول‌ها و فرمول‌ها را حل کنید.
- ارجاع‌های نامعتبر و فهرست مطالب ناقص را اصلاح کنید.
- مشکلات مسیر فایل‌ها و پروژه‌های ZIP را بررسی کنید.
- به‌جای حدس زدن، خطاها را مرحله‌به‌مرحله عیب‌یابی کنید.

## ۱. اولین قانون عیب‌یابی: متن خطا را بخوانید

وقتی PDF ساخته نمی‌شود، اولین کار نباید حذف کردن کدها یا نصب دوباره همه برنامه‌ها باشد.

ابتدا باید بفهمیم **کدام قسمت مشکل دارد**.

خطا ممکن است از یکی از این موارد باشد:

1. نصب نبودن موتور پردازش
2. انتخاب کامپایلر اشتباه
3. نصب نبودن یک بسته
4. نصب نبودن فونت
5. اشتباه تایپی در کد
6. وجود فایل تصویر در مسیر اشتباه
7. ساختار نادرست جدول یا فرمول
8. ناقص بودن فایل‌های پروژه

### روش پیشنهادی

1. فایل TEX را ذخیره کنید.
2. با XeLaTeX پردازش کنید.
3. پنل خطاها و پیام‌ها را باز کنید.
4. اولین خطای اصلی را پیدا کنید.
5. محل خطا را بررسی کنید.
6. فقط همان مشکل را اصلاح کنید.
7. دوباره پردازش کنید.

**نکته مهم:** یک اشتباه کوچک می‌تواند باعث نمایش چندین خطای دیگر شود. بنابراین همیشه از اولین خطای اصلی شروع کنید.

## ۲. تفاوت Error و Warning

### Error — خطا

خطا معمولاً نشان می‌دهد پردازش با مشکلی جدی مواجه شده است.

نمونه:

```text
! Undefined control sequence.
```

این خطا می‌تواند به معنای استفاده از یک دستور ناشناخته باشد.

### Warning — هشدار

هشدار همیشه مانع تولید PDF نمی‌شود.

نمونه:

```text
LaTeX Warning: Reference `fig:test' undefined.
```

این پیام می‌گوید یک ارجاع هنوز قابل شناسایی نیست.

### پیام اطلاع‌رسانی

بعضی پیام‌ها فقط وضعیت پردازش را نشان می‌دهند.

برای مثال، اعلام نام فایل خروجی یا تعداد صفحات PDF لزوماً خطا نیست.

---

## ۳. پیدا کردن خطا در TeXstudio

ابتدا فایل `main.tex` را باز کنید.

سپس:

1. فایل را با `Ctrl + S` ذخیره کنید.
2. عملیات Build را اجرا کنید.
3. قسمت پیام‌ها یا Log را بررسی کنید.
4. روی خطای نمایش‌داده‌شده کلیک کنید، اگر امکان رفتن به محل خطا وجود دارد.
5. خط مربوط در ویرایشگر را بررسی کنید.

### شماره خط همیشه دقیق است؟

نه لزوماً.

گاهی خطا در یک خط ایجاد می‌شود، ولی هنگام پردازش خط بعدی تشخیص داده می‌شود.

برای مثال، بسته نشدن یک آکولاد ممکن است چند خط بعد خطا ایجاد کند.

پس بهتر است چند خط قبل از محل گزارش‌شده را هم بررسی کنید.

## ۴. خطای Undefined control sequence

یکی از رایج‌ترین خطاهای LaTeX:

```text
! Undefined control sequence.
```

### علت

معمولاً یک دستور را اشتباه نوشته‌ایم یا بسته مربوط به آن بارگذاری نشده است.

### مثال اشتباه

```latex
\secton{مقدمه}
```

### کد صحیح

```latex
\section{مقدمه}
```

در مثال اول، حرف `i` در نام دستور جا افتاده است.

### راه‌حل

- املای دستور را بررسی کنید.
- حروف کوچک و بزرگ را بررسی کنید.
- مطمئن شوید بسته مربوط به دستور نصب و بارگذاری شده است.
- پس از اصلاح، دوباره پردازش کنید.

---

## ۵. خطای Missing $ inserted

نمونه:

```text
! Missing $ inserted.
```

### علت رایج

استفاده از بعضی نویسه‌های مخصوص حالت ریاضی در متن عادی.

مثلاً:

```latex
file_name
```

در متن عادی، علامت `_` معنای ویژه‌ای دارد.

### راه‌حل

برای نمایش زیرخط معمولی:

```latex
file\_name
```

یا برای یک فرمول:

```latex
$x_1$
```

### مثال کاربردی

اشتباه:

```latex
دستور lsb_release را اجرا کردیم.
```

صحیح:

```latex
دستور \lr{lsb\_release} را اجرا کردیم.
```

**نکته:** داخل محیط‌هایی مانند `lstlisting` معمولاً نیازی به فرار دادن زیرخط نیست.

## ۶. خطای Runaway argument

نمونه:

```text
Runaway argument?
```

این خطا ممکن است زمانی ایجاد شود که یک آرگومان به‌درستی پایان نیافته باشد.

### مثال اشتباه

```latex
\section{مقدمه
```

در این کد، آکولاد بسته نشده است.

### کد صحیح

```latex
\section{مقدمه}
```

### راه‌حل

- آکولادهای `{` و `}` را بررسی کنید.
- کروشه‌های `[` و `]` را در دستورهای دارای گزینه بررسی کنید.
- مطمئن شوید محیط‌ها به‌درستی بسته شده‌اند.

---

## ۷. خطای Environment undefined

نمونه:

```text
! LaTeX Error: Environment something undefined.
```

### علت

ممکن است نام محیط اشتباه نوشته شده باشد یا بسته مربوط نصب نشده باشد.

### مثال اشتباه

```latex
\begin{itemz}
    \item مورد اول
\end{itemz}
```

### کد صحیح

```latex
\begin{itemize}
    \item مورد اول
\end{itemize}
```

### راه‌حل

ابتدا نام محیط را بررسی کنید.

اگر نام صحیح است، بررسی کنید آیا آن محیط به بسته خاصی نیاز دارد یا خیر.

---

## ۸. خطای File xepersian.sty not found

نمونه:

```text
! LaTeX Error: File `xepersian.sty' not found.
```

### علت

بسته XePersian در توزیع LaTeX موجود نیست یا سیستم نمی‌تواند آن را پیدا کند.

### راه‌حل در اوبونتو

ترمینال را باز کنید:

```bash
sudo apt update
sudo apt install texlive-lang-arabic
```

سپس بررسی کنید:

```bash
kpsewhich xepersian.sty
```

اگر مسیر فایل نمایش داده شد، بسته برای سیستم قابل شناسایی است.

### راه‌حل در ویندوز

اگر از MiKTeX استفاده می‌کنید:

1. MiKTeX Console را باز کنید.
2. وضعیت بسته‌ها و به‌روزرسانی‌ها را بررسی کنید.
3. بسته `xepersian` را جست‌وجو و در صورت نیاز نصب کنید.
4. TeXstudio را دوباره اجرا کنید.

## ۹. خطای انتخاب کامپایلر اشتباه

برای اسناد فارسی این آموزش باید از XeLaTeX استفاده کنیم.

اگر به‌اشتباه pdfLaTeX انتخاب شده باشد، ممکن است خطاهای مرتبط با `fontspec` یا XePersian مشاهده کنید.

### راه‌حل

در TeXstudio:

`Options → Configure TeXstudio → Build`

گزینه `Default Compiler` را روی `XeLaTeX` قرار دهید.

سپس فایل را دوباره پردازش کنید.

### بررسی از طریق ترمینال

در اوبونتو:

```bash
xelatex --version
```

اگر اطلاعات نسخه نمایش داده شود، موتور XeLaTeX قابل اجرا است.

## ۱۰. خطای Font cannot be found

نمونه:

```text
The font "Tahoma" cannot be found.
```

### علت

فونتی که در کد انتخاب کرده‌ایم روی سیستم نصب نیست یا با نام دیگری شناسایی می‌شود.

### راه‌حل در اوبونتو

اگر از فونت Amiri استفاده می‌کنید:

```bash
sudo apt install fonts-hosny-amiri
```

برای بررسی:

```bash
fc-list : family | grep -i Amiri
```

سپس در فایل TEX بنویسید:

```latex
\settextfont{Amiri}
\setlatintextfont{Latin Modern Roman}
```

### راه‌حل در ویندوز

ابتدا بررسی کنید فونت انتخاب‌شده روی ویندوز نصب است.

برای مثال:

```latex
\settextfont{Tahoma}
\setlatintextfont{Times New Roman}
```

اگر فونت دیگری را انتخاب کرده‌اید، نام دقیق آن را در تنظیمات فونت سیستم بررسی کنید.

### نکته مهم

اگر پروژه را از ویندوز به اوبونتو منتقل می‌کنید، ممکن است لازم باشد فونت‌های تعریف‌شده در فایل را تغییر دهید.

## ۱۱. خطای مربوط به بسته fontspec

ممکن است با پیامی مواجه شوید که نشان می‌دهد بسته `fontspec` به XeTeX یا LuaTeX نیاز دارد.

### علت احتمالی

سند با موتور اشتباه، مثلاً pdfLaTeX، پردازش شده است.

### راه‌حل

موتور پردازش را به XeLaTeX تغییر دهید.

اگر خطا باقی ماند، متن دقیق پیام را بررسی کنید؛ زیرا مشکلات نصب یا فونت هم می‌توانند دخیل باشند.

## ۱۲. خطای تصویر پیدا نمی‌شود

نمونه:

```text
File `images/terminal.png' not found.
```

### علت

فایل تصویر در مسیر نوشته‌شده وجود ندارد.

### ساختار صحیح

```text
OS-Lab-Report/
├── main.tex
└── images/
    └── terminal.png
```

### کد صحیح

```latex
\includegraphics[width=0.8\textwidth]{images/terminal.png}
```

### مواردی که باید بررسی کنید

- نام پوشه `images` درست باشد.
- نام فایل تصویر درست باشد.
- پسوند تصویر درست باشد.
- حروف کوچک و بزرگ یکسان باشند.
- مسیر نسبت به محل پردازش پروژه درست باشد.

**نکته لینوکس:** در سیستم‌فایل‌های معمول لینوکس، `Image.png` و `image.png` دو نام متفاوت هستند.

## ۱۳. مشکل نمایش تصویر در محل نامناسب

گاهی تصویر چند خط یا حتی یک صفحه جلوتر نمایش داده می‌شود.

این رفتار لزوماً خطا نیست.

محیط `figure` یک محیط شناور است و LaTeX برای صفحه‌آرایی مناسب می‌تواند محل آن را تغییر دهد.

### راه‌حل اول

از گزینه‌های قرارگیری استفاده کنید:

```latex
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.8\textwidth]{images/terminal.png}
    \caption{محیط ترمینال}
\end{figure}
```

### راه‌حل دوم

اگر لازم است تصویر دقیقاً در محل نوشته‌شده قرار بگیرد، بسته `float` را قبل از `xepersian` بارگذاری کنید:

```latex
\usepackage{float}
```

سپس:

```latex
\begin{figure}[H]
```

اما از `[H]` فقط زمانی استفاده کنید که واقعاً لازم است؛ زیرا ممکن است فاصله‌های خالی نامناسب ایجاد کند.

## ۱۴. خطای Extra alignment tab has been changed to \cr

این خطا معمولاً به ساختار جدول مربوط است.

### مثال اشتباه

```latex
\begin{tabular}{cc}
نام & شماره & وضعیت \\
\end{tabular}
```

در تعریف جدول دو ستون داریم، ولی در سطر سه مقدار نوشته‌ایم.

### کد صحیح

```latex
\begin{tabular}{ccc}
نام & شماره & وضعیت \\
\end{tabular}
```

### راه‌حل

- تعداد ستون‌های تعریف‌شده را بشمارید.
- تعداد علامت‌های `&` هر سطر را بررسی کنید.
- مطمئن شوید سطرها با `\\` پایان یافته‌اند.

---

## ۱۵. مشکل بیرون زدن جدول از صفحه

گاهی جدول بسیار عریض است.

### راه‌حل‌های پیشنهادی

1. عنوان ستون‌ها را کوتاه‌تر کنید.
2. از ستون‌های با عرض مشخص استفاده کنید.
3. جدول را به دو جدول کوچک‌تر تقسیم کنید.
4. در صورت نیاز اندازه فونت جدول را کمی کاهش دهید.

مثال:

```latex
\begin{tabular}{|p{3cm}|p{8cm}|}
\hline
دستور & توضیح \\
\hline
\lr{pwd} & نمایش مسیر پوشه فعلی \\
\hline
\end{tabular}
```

از کوچک کردن بیش از حد فونت خودداری کنید.

## ۱۶. خطای Undefined reference

نمونه:

```text
LaTeX Warning: Reference `fig:terminal' undefined.
```

### علت‌های احتمالی

- برچسب موردنظر وجود ندارد.
- نام برچسب اشتباه نوشته شده است.
- فایل فقط یک بار پردازش شده است.

### نمونه صحیح

```latex
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.7\textwidth]{images/terminal.png}
    \caption{محیط ترمینال}
    \label{fig:terminal}
\end{figure}
```

ارجاع در متن:

```latex
در شکل \ref{fig:terminal} محیط ترمینال نمایش داده شده است.
```

### راه‌حل

ابتدا نام برچسب‌ها را بررسی کنید.

سپس فایل را دو بار با XeLaTeX پردازش کنید.

## ۱۷. مشکل فهرست مطالب خالی یا ناقص

اگر از دستور زیر استفاده کرده‌اید:

```latex
\tableofcontents
```

اما فهرست مطالب کامل نیست، احتمالاً اطلاعات فهرست هنوز به‌روزرسانی نشده است.

### راه‌حل

1. فایل را ذخیره کنید.
2. XeLaTeX را اجرا کنید.
3. دوباره XeLaTeX را اجرا کنید.
4. PDF را بررسی کنید.

### نکته

عنوان‌هایی که با دستور ستاره‌دار ایجاد می‌شوند، مانند:

```latex
\section*{مقدمه}
```

به‌صورت پیش‌فرض مانند بخش‌های معمولی در فهرست مطالب شماره‌دار ثبت نمی‌شوند.

برای گزارش‌های معمول، اگر شماره‌گذاری و فهرست خودکار می‌خواهید، از `\section` استفاده کنید.

## ۱۸. خطای Missing \begin{document}

نمونه:

```text
! LaTeX Error: Missing \begin{document}.
```

### علت

ممکن است ساختار سند ناقص باشد یا دستوری در محل نامناسب نوشته شده باشد.

### ساختار پایه صحیح

```latex
\documentclass{article}

\usepackage{xepersian}

\settextfont{Tahoma}

\begin{document}

سلام!

\end{document}
```

برای اوبونتو، در صورت نبود Tahoma از فونت نصب‌شده‌ای مانند Amiri استفاده کنید.

### راه‌حل

مطمئن شوید:

- دستور `\documentclass` در ابتدای فایل وجود دارد.
- بسته‌ها قبل از `\begin{document}` نوشته شده‌اند.
- متن اصلی داخل محیط `document` قرار دارد.
- دستور `\end{document}` در پایان سند وجود دارد.

## ۱۹. خطای بسته نشدن محیط

مثلاً:

```latex
\begin{itemize}
    \item مورد اول
    \item مورد دوم
```

در این مثال محیط `itemize` بسته نشده است.

### کد صحیح

```latex
\begin{itemize}
    \item مورد اول
    \item مورد دوم
\end{itemize}
```

هر محیطی که با `\begin{...}` شروع می‌شود، باید با `\end{...}` مناسب پایان یابد.

## ۲۰. مشکل تولید نشدن PDF در TeXstudio

اگر با زدن F5 خروجی PDF تولید نشد، این مراحل را انجام دهید.

### مرحله اول: بررسی ذخیره بودن فایل

فایل باید با پسوند `.tex` ذخیره شده باشد.

مثلاً:

`main.tex`

### مرحله دوم: بررسی موتور پردازش

مطمئن شوید `XeLaTeX` انتخاب شده است.

### مرحله سوم: بررسی پیام‌ها

پنل خطا و Log را بررسی کنید.

### مرحله چهارم: بررسی فایل خروجی

پوشه پروژه را باز کنید و ببینید فایل PDF ساخته شده است یا خیر.

### مرحله پنجم: آزمایش از ترمینال

در اوبونتو، داخل پوشه پروژه اجرا کنید:

```bash
xelatex -halt-on-error main.tex
```

گزینه `-halt-on-error` باعث می‌شود پردازش در اولین خطای جدی متوقف شود.

این روش پیدا کردن خطای اصلی را آسان‌تر می‌کند.

**توجه:** این دستور باید در پوشه‌ای اجرا شود که فایل `main.tex` داخل آن قرار دارد.

## ۲۱. خطای Command not found در اوبونتو

نمونه:

```text
xelatex: command not found
```

### علت

ممکن است XeLaTeX نصب نباشد یا در مسیر اجرایی سیستم شناسایی نشود.

### راه‌حل

```bash
sudo apt update
sudo apt install texlive-xetex
```

سپس:

```bash
xelatex --version
```

اگر نسخه نمایش داده شد، موتور قابل اجرا است.

## ۲۲. خطای Unable to locate package

نمونه:

```text
E: Unable to locate package texstudio
```

### علت‌های احتمالی

- فهرست بسته‌ها به‌روز نیست.
- مخزن موردنیاز فعال نیست.
- نام بسته اشتباه است.
- نسخه یا تنظیمات مخازن سیستم متفاوت است.

### راه‌حل اولیه

```bash
sudo apt update
```

سپس:

```bash
apt search texstudio
```

اگر بسته در فهرست وجود داشت، نصب را دوباره امتحان کنید:

```bash
sudo apt install texstudio
```

اگر همچنان پیدا نشد، وضعیت مخازن فعال و نسخه اوبونتو را بررسی کنید.

---

## ۲۳. مشکل نصب بسته‌ها در MiKTeX

در ویندوز ممکن است هنگام پردازش سند، MiKTeX اعلام کند بسته‌ای نصب نیست.

### راه‌حل

1. اتصال اینترنت را بررسی کنید.
2. MiKTeX Console را باز کنید.
3. به‌روزرسانی‌های موجود را بررسی و نصب کنید.
4. تنظیمات نصب خودکار بسته‌های گم‌شده را بررسی کنید.
5. بسته موردنیاز را در بخش Packages جست‌وجو کنید.
6. دوباره پردازش کنید.

### نکته

اگر MiKTeX برای کاربر فعلی و همچنین در حالت مدیریتی نصب شده باشد، باید توجه کنید تنظیمات و بسته‌ها را در همان حالتی مدیریت کنید که توزیع فعال شما استفاده می‌کند.

## ۲۶. وقتی نمی‌دانیم مشکل از کجاست چه کنیم؟

از روش **حداقل مثال قابل بازتولید** استفاده کنید.

به این روش معمولاً *Minimal Working Example* یا به‌اختصار **MWE** گفته می‌شود.

### ایده اصلی

یک فایل کوچک بسازید که فقط بخش مشکل‌دار را داشته باشد.

مثلاً برای بررسی نصب XePersian:

```latex
\documentclass{article}

\usepackage{xepersian}

\settextfont{Tahoma}

\begin{document}

سلام دنیا!

\end{document}
```

در اوبونتو در صورت نیاز، Tahoma را با Amiri جایگزین کنید.

### نتیجه آزمون

اگر این فایل ساده هم پردازش نمی‌شود، احتمالاً مشکل از تنظیمات، نصب بسته‌ها یا فونت است.

اگر فایل ساده درست پردازش می‌شود ولی گزارش اصلی خطا دارد، احتمالاً باید کد یا فایل‌های وابسته گزارش را بررسی کنید.

این روش کمک می‌کند مشکل را سریع‌تر محدود کنیم.

## ۲۷. جدول سریع تشخیص خطا

| پیام یا مشکل | علت احتمالی | اولین اقدام |
|---|---|---|
| `Undefined control sequence` | دستور اشتباه یا بسته ناموجود | بررسی نام دستور |
| `Missing $ inserted` | نویسه ریاضی در متن عادی | بررسی `_` و `^` |
| `Runaway argument` | آرگومان ناقص | بررسی آکولادها |
| `xepersian.sty not found` | بسته موجود نیست | بررسی نصب XePersian |
| `Font cannot be found` | فونت نصب نیست | بررسی نام و نصب فونت |
| `File ... not found` | مسیر فایل اشتباه است | بررسی پوشه و نام فایل |
| `Undefined reference` | برچسب نامعتبر یا پردازش ناکافی | بررسی label و اجرای دوباره |
| `xelatex: command not found` | موتور نصب یا شناسایی نشده | بررسی نصب XeLaTeX |
| PDF ساخته نمی‌شود | خطای کد یا تنظیمات | بررسی اولین خطای Log |

## ۲۸. تمرین عملی پایان درس

برای اینکه عیب‌یابی را واقعاً یاد بگیرید، چند خطای کنترل‌شده ایجاد کنید.

### تمرین اول: دستور اشتباه

دستور `\section` را عمداً به `\secton` تغییر دهید.

سند را پردازش کنید.

خطا را پیدا کرده و اصلاح کنید.

### تمرین دوم: آکولاد ناقص

یک آکولاد بسته را حذف کنید.

خطای ایجادشده را بررسی کنید.

سپس آکولاد را برگردانید.

### تمرین سوم: تصویر ناموجود

در یک پروژه دارای تصویر، نام فایل را عمداً اشتباه بنویسید.

پیام خطا را مشاهده کنید.

سپس مسیر را اصلاح کنید.

### تمرین چهارم: ارجاع نامعتبر

یک ارجاع به برچسب ناموجود ایجاد کنید:

```latex
شکل \ref{fig:unknown}
```

سند را پردازش کنید و هشدار را بررسی کنید.

سپس ارجاع را حذف کنید یا برچسب صحیح را قرار دهید.

### تمرین پنجم: بررسی کامپایلر

تنظیمات XeLaTeX را بررسی کنید و یک سند فارسی سالم را پردازش کنید.

**نکته:** این تمرین‌ها را روی یک نسخه آزمایشی از پروژه انجام دهید تا گزارش اصلی آسیب نبیند.
